# API改善 008: Neon DBクライアントの再利用

## 目的

同一リクエスト内の各ルート処理で`getDb(c.env)`が複数回呼ばれ、NeonクライアントとDrizzleラッパーが毎回生成されていた。接続先URL単位でDBオブジェクトを再利用する。

## 変更内容

- `DATABASE_URL`をキーにしたプロセス内キャッシュを追加
- 未設定URLは従来どおりエラーにする
- クエリ、トランザクション、APIレスポンスの仕様は変更しない

## 注意

キャッシュするのはDBクライアントラッパーであり、リクエストデータや認証情報は保持しない。Cloudflare Workerの環境ごとに自然に分離される。
